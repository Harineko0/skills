# Google Chat・チームチャットの文体

しろくま電力 Google Chat の過去 1 年分（対人 189 件: 日本語 150 / 英語 39）の送信履歴とスレッド文脈から抽出した実践ルール。

## 1. 相手と場面で 5 つのレジスターを切り替える

| 場面 | 目安の長さ | 敬語・語尾 | 末尾 `。` | 絵文字 |
|---|---|---|---|---|
| **即応・承諾・確認** | 1〜2 行 (15〜50 字) | `承知しました` / `了解です` / `ありがとうございます` | 原則省く | `🫡` / `🙇` |
| **依頼・設定変更** | 2〜6 行 + 手順/URL | `〜お願いいたします` / `〜いただけますでしょうか` | 文中は付ける・末尾は省きやすい | `🙇` / `🙏` |
| **技術議論・DM（同僚）** | 1〜4 行 (40〜140 字) | `〜ですね` / `〜かもです` / `なるほどです` | 原則省く | 0〜1 個 (`🙇`/`🫡`/`🤔`) |
| **全体連絡・契約・謝罪** | 3〜6 行 (100〜300 字) | `〜いたします` / `大変申し訳ありません` | 基本付ける | 0〜1 個（契約・謝罪は 0） |
| **英語チャット** | 1〜5 行 | 丁寧かつ簡潔な開発者英語 (`Thank you...` / `I suppose...`) | `.` を付ける | 0〜1 個 (`🙏`/`🫡`/`🙂‍↕️`/`😂`) |

## 2. 冒頭・メンション・結び

- **冒頭挨拶は基本なし**: 既知のスレッドや DM では `お世話になっております。陶山です。` は使わず、直前発言への反応（`ありがとうございます🙇` / `承知しました🫡` / `なるほどです`）または本題から入る。
- **時間帯の挨拶・初対面**:
  - 依頼を切り出すときは `@相手名 お疲れ様です。`（休日気遣いは `お休みのところ失礼します。`）。
  - 初対面の相手には `@相手名 さん` または `相手名さん\nはじめまして、ゆにねこです。` / `現在業務委託で入らせていただいております、ゆにねこです。` を使う。
- **メンションの敬称**: Google Chat の `@メンション` を付ける既知の同僚には、多くの場合 `さん` を付けない（`@相手名 お疲れ様です。`）。メンションなしの本文中で人を指すときは `〇〇さん` を付ける。英語では相手から外してと言われるまで `Name-san` を使う。
- **トリアージ接頭辞**: 共有・質問・状態報告を 1 語で示すとき、文頭に `FYI ` / `btw: ` / `ask: ` / `status: `、文末に `cc.@相手名` を置くことがある。
- **結び**: 継続中のやり取りや承諾・回答では `よろしくお願いいたします` を置かず内容で言い切る（約 8 割）。新しい依頼・契約・初回挨拶のときだけ末尾に `よろしくお願いいたします`（または `お願いできれば助かります🙇`）を添える。

## 3. メッセージに入れる情報量と構成

- **理由・制約を 1 節で添える**: 依頼や判断の背後に技術的・運用上の理由がある場合、言い訳っぽくせず端的に書く（例: `今は無料プランで済ませるために分けております`、`実機の動作を反映するため、ガイドはリリース後に作成いたします`）。
- **相手がすぐ動ける具体値を入れる**: URL / `go/` リンク / エラー番号 `(404)` / 設定名 / 権限名 / UI 遷移パスを省略しない。
- **手順・設定値の並べ方**: Markdown の ```` ``` ```` コードブロックや `` `インラインコード` ``、`- ` 箇条書きの乱用は避け、プレーンテキストの改行・`Key: Value`・`>` や `→` で書く。
  - パス例: `デバイス > Chrome > Settings > User` または `デバイス\n  → Chrome\n    → アプリと拡張機能`
  - 設定値例: `拡張機能名 : ...\nURL: https://...\nID: ...`
- **選択肢と暫定方針を先に出す**: 確認事項があるときは「A か B の 2 通りがありますが、どちらがよろしいでしょうか？」「もし未契約ならしばらくは〜しようかと思います」「特になければ構いませんのでご放念ください」のように相手の判断負荷を下げる。
- **補足を 1 通に詰め込みすぎない**: 長い前提と補足が混ざるときは、本体を短く書き、末尾に `補足:` を置くか、実運用では短文で分けて送る（例: 本体送信後に `なお〜🫡` やリンクだけ追投）。

## 4. 絵文字・句読点・表記の細部（本人らしさの決め手）

- **絵文字の語彙（これ以外は原則使わない）**:
  - `🙇`（最頻）: お礼・依頼・お詫び・お疲れ様ですの行末にスペースなしで密着（`ありがとうございます🙇`、`確認お願いいたします🙇`、`すみません🙇`）。
  - `🫡`（高頻度）: 承諾・調査着手・修正報告・自分の担当宣言（`了解です🫡`、`承知しました🫡`、`確認します🫡`、`修正しておきます🫡`）。
  - `🙏`（限定）: 具体的なお願いや、文中でのお礼（`お願いできますでしょうか🙏`、`ありがとうございます🙏 ...`、`sorry for replying late 🙏`）。
  - `🤔` / `🙂‍↕️` / `😂`: 技術的な軽い相談や英語チャットの雑談的やり取りに限りごく稀に使う。
  - 頻度は全体の 3〜4 割程度、1 通あたり 0〜1 個（強い感謝のときのみ `🙇🙇`）。`💦` `✨` `🎉` `💪` `😊` やカスタム絵文字は本文に入れない。
- **句点 `。` と読点 `、`**:
  - 短文・返信・確認の文末は `。` を付けない（`確認しました`、`変更しておきます`、`〜ですね`、`〜でしょうか？`）。
  - 2 つの短い節を 1 行に収めるときは `。` ではなく `、` でつなぐ（`承知しました、ありがとうございます🙇`、`作成いただきありがとうございます、確認しました`、`ありがとうございます、transfer ですので...`）。
  - 複数文が続く説明文や契約・謝罪メッセージでは文中に `。` を使う。
- **日本語と英単語のスペース**: 日本語文中の英単語・URL・`go/` リンクの前後には半角スペースを入れるのが基本（`go/ リンク`、`Chrome Extension が`、`Apple Business アカウント`、`Android アプリ`）。ただし助詞直前など一部で詰まることは許容する（`Chromeの`、`Androidは`）。
- **軽さ・笑い表現**: 親しい相手との技術雑談でのみ文末に `w` を 1 つ置くことがある（`これはちょっと心配ですねw`）。`笑` や `草` は使わない。
- **括弧と感嘆符**: 技術補足は半角括弧 `( ... )` が多く、一般補足には全角 `（...）` も混ざる。嬉しいときや強めの感謝は `ありがとうございます！` / `了解です!` を使う。疑問符は日本語では全角 `？` を基本とする。
- **英語引用返信**: 相手の番号付きコメント等に細かく答えるときは、`>` 記号を使わず相手の該当文をそのまま貼り、改行して直下に自分の回答を書く。

## 5. 文脈別実例

- **即応・承諾**
  - `承知しました🫡`
  - `了解です、デフォルトで全員編集可に変更しておきますね`
  - `ありがとうございます🙇　確認いたしました`
- **技術回答・状況説明（DM・開発ch）**
  - `Androidは work profile を作成すれば自動的にインストールされますね\nガイドに書いておきますね`
  - `Chromeのアドレスバーで直接開いた時はリダイレクトされなくて、 https://go/site のようなリンク形式になっている場合はリダイレクトされますね`
  - `なるほど。\n仮に私が作るシステムで完全なACLが実装できたとしても、現状は一次情報のACLが曖昧だからそもそも非公開の情報を取り扱えない感じですね`
- **依頼（他チーム・情シス）**
  - `@相手名 お疲れ様です。Chrome Extension がリリース完了しましたので、お手すきの際にGoogle Admin から設定をお願いいたします🙇\n\nデバイス > Chrome > Settings > User\n...\nよろしくお願いいたします。`
- **遅延謝罪・契約関連**
  - `返信が遅くなってすみません。まず当時の提案資料を共有します。\n<URL>\n...まずはこちらをご確認いただけると助かります。よろしくお願いいたします。`
- **英語返信**
  - `I'm sorry for replying late 🙏\nType go/ on the address bar or just navigate to <URL> and click "Create link" button.`
  - `If the information is unclear, please feel free to ask questions🙏`

## 6. 出力前チェック

1. メール用の `お世話になっております。陶山です。` や過剰な結びが混ざっていないか。
2. 短文・中距離返信の末尾に不必要な `。` を付けすぎていないか（2 節は `、` でつないだか）。
3. Markdown のコードブロック・バッククォート・箇条書き記号をプレーンテキストへ戻したか。
4. 絵文字は `🙇` `🫡` `🙏` 中心に 0〜1 個へ収まり、本文に過剰な装飾絵文字が混ざっていないか。
5. 相手が即判断・即操作できる情報（理由・URL・設定値・代替案）が欠けていないか。
